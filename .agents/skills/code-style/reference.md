# Code style: reference

The cases of skill `code-style` that serve a minority of steps; [SKILL.md](SKILL.md) names each section with when to read it.

## Lookups

- A lookup keyed by caller input or a catalog name reads own keys only (`Object.prototype.hasOwnProperty.call`, as `hasOwn` in `src/generate/tables.ts`, or a `Map`; `Object.hasOwn` is past ES2019, TS2550): `constructor`, `toString`, `__proto__` and `caller` crashed or masked lookups (#48, #399, #405, #486); `Object.create(null)` changes every later inherited lookup, and escapes through an export.

## Error messages

An error says what to do (SKILL.md § JSDoc and errors), and:

- Its advice is run as written, on each call and kind of value that throws it ("spread it" split a string into characters, #235), at each position that reaches it and on Postgres (`db.self`, advised for a write, runs only in `update()` and a filter: #666, #677); a warning firing in more cases is reread for each; advice moving where a transaction begins says what it costs, probed by a read, a write and an insert of one key (#486, #492). A tool's "run X to fix it" is tested by running X on that exact state (a `queries.ts` with conflict markers, chapter #62's review).
- A doc that quotes a tool's message quotes it from a run of the documented install, not from the code, and runs the fix it prints: `peers.ts` checks its peers in order, so `--legacy-peer-deps` stops on another peer first, and the printed `npm install @pgcast/pgcast` failed with `ERESOLVE` again (#873).
- A message the docs quote is one template, each interpolation one word, and holds no backtick if a table cell quotes it: otherwise `check-prose.mjs` says only "is no message of zapatos/db", not that a ternary or a phrase in the template blocks the match (#569, #596, #647, #748). It matches by source text: renaming an interpolated variable breaks every quote of the message; a SQL block matches its probe's queries exactly (no comment at a line's end, `…` for a number that changes from run to run) (#727, #730).

## Claims

Each claim (SKILL.md § Claims), case by case:

- **A run, not a reading**: the exact code the page shows (`${'films'}`, not `films`), as the call its sentence describes, on the docs schema (a probe write on a table nothing references, or a foreign key stops it); the outer call too (an outer `selectOne()` hides duplicated rows), a chain as the reader writes it, the CLI from `npm pack`. A claim from an issue, a brief, a review or an "Expected" (advice, a suggested guard) is a hypothesis until run; before the plan, search the tests that freeze the behaviour and the pages that state it (#51, #168, #501).
- **At more than one value**: another size, isolation level or Postgres version (CI's oldest, 14, for a refusal or an error code: #522, #573), the empty result (`rows[0]`), a warm pool for a race, a realistic table for a plan (`EXPLAIN (ANALYZE)`), what node-postgres hands over (`date` as a `Date`, `POINT` as `{ x, y }`; `pg.DatabaseError` from pg 8.6, on its tarballs), in a time zone east of UTC (pg sends local time), and west of it with a half-hour offset for a copied date formatter (#709), with `extra_float_digits=0` in `db.options` (a `float4` then arrives rounded: order in SQL, #49), on data where the two readings differ; each outer selector under each int8 parser (a count is `"2"` by default, `2` with `Number`; `select()` gives JSON) and a subquery with no row (JSON `null` under its key) (#756); a setting from each source (fresh, `SET`, `ALTER DATABASE`/`ROLE … SET`, `-c` in `options`; a role-level case by `ALTER ROLE CURRENT_USER IN DATABASE <probe> SET`, dropped with the probe), its default worded "what `RESET` gives" (#741); a "from Node N" claim, `typeof X` on each major before N (`npx -p node@<v>`, #521).
- **At every position it covers**: each row of an array, line 1 and a later line, a `where` and an `update()`, one nesting past the named ones, each outer call (`select()`, `selectOne()`, `selectExactlyOne()` with and without its opt-in, `count()`), at `.run()` and nested in `lateral` or `extras`, a `vals({…})` in an `insert()` value and in a `sql` template you write (#164, #341, #420, #482, #484, #638, #686); each API a sentence names, in each direction, its error path too (`err.constraint`): "as on a `pg.Pool`" held for `query()` while PGlite's `transaction()` did the opposite (#712, #729).
- **"Every", "only", "never"** are searched for their exceptions (`git grep` the name); "takes only" gets a negative `tsc` probe, "cannot mean anything in SQL" a run in Postgres, "the catalog doesn't say" the catalog table (`pg_constraint`). A security rule lists every exemption: row-level security has three (superuser, an owner without `FORCE`, `BYPASSRLS`), and a sentence naming two leaks data for its reader (#747).
- **A shortened rule keeps its condition**, or links it: a guide restating a reference, a docs bullet, a JSDoc, a merged note, a CHANGELOG headline and its "Unchanged" list, a later version's contract (decision 003's narrowest wording, both exceptions), a quote of Zapatos (its subject and surrounding clauses). Each carries every clause (an option such as `undefinedMeansMissing`, a mode, an exception on an open issue); a list of conditions has one test per clause (#164, #271, #402, #485).
- **What changed is searched for**: after a change of behaviour, an added exception, a closed issue or dropped advice, `git grep` the old phrase and other wordings, the issue number, the message (a distinctive fragment of its old text, inline snapshots included), its SQLSTATE codes, the rows that list the value's siblings, across the repo (`website/` in both languages, `SECURITY.md`, JSDoc and messages in `src/`); then reread the sentence framing each hit (a list's lead-in, a page's general rules, "never", "always") (stale pages: #32, #96, #179, #251, #447, #492, #645, #655, #686).
- **A CHANGELOG entry**: its `Changed:` and `Unchanged:` sub-bullets carry each other's conditions, an `Unchanged:` holds no behaviour change, each path it states (a Postgres error past the type too) is frozen by a test (#548, #575, #632); a `Changed:` telling users what to add marks a break (#605); an "except" lists each value (#530). A line from a review is replayed on the last release, not master (#553); an entry a later PR rewrote is reread clause by clause against the code (#686).
- **What will move** is tied back: a known defect links its open issue, checked by `gh issue view <n>` on that number (#701 linked PGlite's adapter to postgres.js's), whose comment points at the line; no count of a list that grows ("the two opt-ins", a living report's tally).

## Laterals

Going further than Zapatos (SKILL.md § Further than Zapatos):

- Its laterals typed by foreign keys and its written limits (§ lateral, Limitations) stay, as note 007 decides (choice D: a core helper saves a type, never a line nor the SQL; a revival is a revision of the note): `parent<T.Column>('c')` checks the column only, the docs show a lateral on each kind of key, and `selectExactlyOne` is written by hand when the FK is `NOT NULL`.
