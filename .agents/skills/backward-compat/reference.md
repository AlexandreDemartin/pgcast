# Staying backward compatible: reference

The cases of skill `backward-compat` that serve a minority of steps; [SKILL.md](SKILL.md) names each section with when to read it.

## Fixing an existing bug

- A deprecation trigger follows the compiled SQL (which columns still come from `EXCLUDED`), not the input's shape, or the 7.0 default refuses calls that lose nothing (#27); a run-time check copied from a type inherits its gaps, so it follows the Postgres semantics behind the type (`SerializableRODeferrable` satisfies every read-only level, #486).
- An error moved from `.run()` to build time is a named change: a synchronous throw, not a rejection, a plain `Error`, not a `DatabaseError` (`.catch()`, `Promise.allSettled`, `isDatabaseError`). Probe it with `.run(pool).catch(h)` outside any `async`.
- **A new refusal** where 6.6.1 rejected from `.run()` throws while compiling: a fragment whose `compile` throws, in the query's expressions so `copy()` keeps it (#167, #235), frozen through `.run()`; its docs say "throws while compiling, so `.run()` rejects", as its test asserts. Its probe table crosses each value with each shortcut and row position, and with the inputs the existing refusals catch first (#244, #341); a type slot that still takes the call is narrowed in the PR, or the gap filed (#503). A walk over caller data is iterative (an explicit stack), runs where the fragment compiles (an array changed after the call), and is tested with a refused item after a plain one in a nested array and a cycle not through the root (#638, #647); a large built-in is refused before its keys are listed (#543).
- **A once-per-process warning** is tested on `src/db` after `vi.resetModules()`, which reloads TypeScript sources only: the root's `db.js` shim loads `dist` through Node's CommonJS cache, which it does not reset (#703).
- **A caller's object is read as 6.6.1 read it**: the same keys, as often; no copy that rebuilds it (`{ ...x }`, `Object.fromEntries`) and loses getters, inherited or non-enumerable keys; a throwing getter or Proxy never breaks every query (`getConfig()`: #249, #257, #501, #508). A read or trap-count test has a case where the runtimes differ (an own getter), a `Proxy` row with no own key and a key added to `Object.prototype`. A guard comparing a value with `Object.prototype`'s uses `Object.is` (`NaN`) and the property descriptor, data or accessor (`get`, `set`, `{ get, set }`, `__proto__`), with a row per descriptor shape at each caller of the shared helper (`callerValue()` in `utils.ts`) (#550, #553, #558, #598).
- **A result that changes** (a rejection turned into a value, or the reverse) has a `Changed:` sub-bullet saying what the caller gets, one clause per path (a pool and a plain client), its row in `switching.md` § Find the calls whose result changes, and an "except" in the report's class cell (#163, #502, #506); a PR that extends a refusal extends its row, and a write refusal's row also names a `vals({…})` of a query you write (#686).

## Removing an option

- **Its refusal** covers every exported function that read the key on master: `git grep <key> origin/master -- src`, each read traced up to its exported caller (`definitionForRelationInSchema()` was missed, #982). It reads the key as master did, by spread (own keys) or by property access (inherited too), or a 7.x reader switches without a word (#974).
- **`null` and `undefined`**: a guard calling `Object.prototype.hasOwnProperty.call(arg, …)` throws where `{ ...arg }` did not, and a removed `suppliedConfig.key` no longer throws its TypeError: replay `f(undefined)` and `f(null)` on master and the branch (#982, #986).
- **What it leaves**: the equality test of the variant made default ("same types") now compares the output with itself, so the proof moves to the PR, a probe against master's output (#975), completed for every variant in under a second by expanding each snapshot diff's added line through the old template and comparing it with the removed one (#989). Data that records the old behaviour with no test asserting it any more (6.6.1's `old` data of the block cases) stays only as the record behind a docs table, and says so (#983). A docs sentence listing the cases a type refuses compiles each case kept and each taken out, and is diffed against its JSDoc twin: "X, Y, and Z unless <option>" lost X and Y with Z (#985).

## Replay, do not reason

- **Each case** is built with its own copy's `sql`, `param` and `Default` (`instanceof` and symbols do not cross copies), under a `SAVEPOINT` rolled back after each run, a `setval` inside it (a sequence is not rolled back, #529); each value is snapshotted as read (`{ ...x }`, getters by name), or a shared live object or `JSON.stringify` shows a regression that is not there (#245).
- **What**: the stored value, not only whether it throws (`pg` stores an object as JSON, anything else through `toString()`); each write path and column type that took the old value (text, `jsonb`, an array element); the negated forms and the writes (`isNotIn`, `deletes`); `undefined` and `null`, for projects without `strictNullChecks`; odd shapes (a `null` row, a counting and a throwing getter, a Proxy, a class instance, inherited, non-enumerable or symbol keys, prototype names, a subclass of each refused built-in, an array-like); falsy values set under a truthy default (`0` tells `??` from `||`) and at each level; `null` options at each entry point; what a JSON config holds (`null`, a comma-separated list); each value `pg` returns through the column's old `Selectable` type (an interval typed `string` is an object), and a one-key variant of each refused built-in (#503, #530); `null` and `undefined` items of each array option (`order`, `lock`, #558); each conversion path of a value apart (#607); a CLI argument in each position (#557).
- **A generated type said to be Zapatos 6.6.1's** is generated by 6.6.1's `dist/generate` (cached under `node_modules/.cache/pgcast-zapatos-661/`), not read from pgcast's, which #654 changed after 6.6.1; a rewording that moves a claim's reference point (from 7.x's written-out union to 6.6.1's) replays each case against the new one; the last pgcast release is usually the safer reference (#989).
- **Types**: a grid of calls (each column × a literal of each Postgres type) compiled against 6.6.1's declarations and the branch's, diffed both ways, line by line: a union member can widen a literal or let a new call through. It adds the exported generics as consumers write them (`db.RangeString<number>`), generic forwarders, an assignment to `typeof fn`, a union per refused shape, an exhaustive `switch`, and in output position `Record<T, X>`, a mapped type and conditionals in three forms; inferred types compare by a probe file's emitted `.d.ts` (`tsc --declaration --emitDeclarationOnly`). A grid cell assigns a value (`const x: L = '1'`), never `{} as never`, which always compiles; `===` does not narrow a union of pattern template literals. Overloads are no neutral way to widen a generic export: passed as an argument (`.map`, `.then`) they lose generic inference, and overloading an export that had one signature (`sql`, `eq()`, `param()`) is a break by default (#276, #282, #520), probed by `traced(db.sql)`, a value assigned to `typeof db.sql` and a contextual arrow under `noImplicitAny`. To widen an overloaded one, add an overload and keep 6.6.1's last, which `Parameters` and `ReturnType` read; test an inline literal, a variable, `as const` and a `readonly` array, each resolved apart (#682, #684). A cell uses the value it reads back (`run()` is `any` after `instanceof`, #655). A widened writable field (`frag.run`) moves one cell per path that reads it: a contextual arrow, `typeof`, `Pick`, a spy, a generic or `infer`, a library's `.d.ts` re-export; each path gets its own probe, and the docs its own remedy or "none", proved at that path (#700). An alias that is both a callback's client and a user's parameter gets cells on its own property (`NonNullable<A['_zapatos']>['isolationLevel']`) and inside a helper's body (an assignment, an exhaustive `switch`, forwarding, a `Record` keyed by the property), not only on the callback: a gap kept by Document is frozen there too (#693). A `never` result turned into a real type is probed combined (a union, a ternary, several `return`s) and computed from (`keyof`, an indexed access, a conditional) (#34, #38, #40, #41, #43, #185, #462).
