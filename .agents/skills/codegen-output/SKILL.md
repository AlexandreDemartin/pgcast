# Codegen output

The generated file (`zapatos/schema.d.ts`) is compiled by every user project: its content is part of the API (skill `backward-compat`).

## Rules

- **Snapshot first**: the output generated from `test/fixtures/schema.sql` is frozen; every snapshot diff is explained line by line in the PR.
- **Default output unchanged**: anything new (FKs, functions, validators) sits behind a config option, default = 6.6.1 output. Otherwise a stop point. Off, files and notes stay master's (skill `backward-compat` § Fixing an existing bug); each key that changes the output has its `variants` entry (a frozen, compiled snapshot), and a note's tests run every variant and freeze the order of notes that fire together; a census of every note gets a new note added to its expectations, never filtered out (#44, #45, #166, #447).
- **A note lists what changes**: an opt-in's note names exactly the columns whose lines or placeholders differ between the key on and off. One test over a set of shapes, a column per kind its lead-in names, under each option that widens the list (`domainsTypedByContext`), asserts the list and the lead-in word for word; the listing reads a domain's root as the typing does, once every relation is read (#519, #522). A fix to a placeholder's text makes the note on placeholders on disk fire for files an earlier version wrote: check its message (#669).
- **Deterministic**: explicitly sorted order (`ORDER BY` + name), never `pg_catalog`'s order nor query timing. Relations are read concurrently (`Promise.all` in `tsOutput.ts`): a value they share (`customTypes`, its imports and origins) is merged whatever the order, through state the run already shares, or a new out-parameter written under Decided alone when the order needs data per column (#669), and tested through `placeholdersInEveryOrder` (`test/integration/codegen.test.ts`); no `await` inside `definitionForRelationInSchema`'s row loop. Within one relation, 6.6.1's winner is kept by the position Postgres returns the column at, not by its name compared in JavaScript; a determinism fix is replayed on the reviewer's grid and on the cases whose winner was already fixed (#669). A byte-for-byte proof leaves #42's shared placeholders out or compares several runs; "only where 6.6.1's output already varied" is probed with `db: { max: 1 }` and the schemas in both orders (#184, #449, #484, #490).
- **Qualify by schema**: every introspection query filters on `pg_namespace`, never on the object name alone. A branch on a built-in type's name checks `pg_catalog` too, an enum is looked up in its type's own schema (`otherEnums[udtSchema]`), not the relation's, and an array is not known by a `_` prefix (Postgres names `tag[]` `_tag_1` beside an enum `_tag`); each is tested against an enum, a composite and a domain named like the built-in (`int4`, `interval`) in a user schema, beside an array of it (#484, #519, #522).
- **Hostile catalogs**: a change to an introspection query is compared with the catalog itself (`pg_index` by `indrelid`) over partitions in another schema, inheritance, names holding `"`, `.` or `[]`, a materialised view (its own query) and objects in a transient state (`indisvalid`); a filter on a `LEFT JOIN`'s right table goes in its `ON`; a fact read two ways (`information_schema` for tables, `pg_catalog` for materialised views) gets one test per path, on data where they differ (#37, #42, #43, #47, #166). A reader of catalog SQL text (`pg_get_constraintdef()`) matches the forms Postgres stores (`VALUE = ANY (ARRAY[…])`, a one-value `IN` as `=`), with `standard_conforming_strings` off too (a backslash comes back doubled), and filters on `contype` (from 17, a domain's `NOT NULL` is a row) (#646).
- **The generated output compiles**: `npm run typecheck` compiles the fixture's output. A claim about the output is replayed with `skipLibCheck` both ways (it hides unresolved names as `any`), with 6.6.1's placeholders still on disk (the generator never rewrites them), in a prefixed and an unprefixed schema, through the CLI when `cliConfig.ts` changes, as a child process for its exit code (#557); parsing (`syntaxErrors()`) and compiling are two checks (#48, #184, #399, #487). Each import a placeholder writes compiles under each `customTypesTransform`, with `skipLibCheck: false` (TS2440 hides in the build), and the clash rule matches the base type (`name`, `name[]`), not the names alone (#648, #651). Two runs are compared with `db: { max: 1 }`, queries sorted without their sequence numbers (#557, #648).
- **The docs schema follows**: after the root `npm run build`, `cd website && npm run docs:schema`, and commit what changes in `website/zapatos/`; the `docs` job fails on a stale one.
- **Canary**: an incompatible change of format increments `SchemaVersionCanary` (`src/db/canary.ts` and `src/generate/tsOutput.ts`): a stop point.
- **`zapatos/*` strings** unchanged (note 002).
- **Comments**: a `COMMENT ON` text goes into a JSDoc; `*/` must be neutralised in the whole string, template text included, by one quoting helper per kind of string (`src/generate/quote.ts`). Line ends are normalised first (`/^/gm` matches after `\r`, U+2028, U+2029). What TypeScript reads (a tag, a hover, a strike-through) is checked with its own parser (`ts.getJSDocTags`, `getQuickInfoAtPosition`) on the real `tsForConfig` output, margins included, against master's output; any doubt keeps master's layout. A rule that predicts how TypeScript reads the output ships with a seeded fuzz, `typescript` as the oracle, over the parser's token classes (`\` escapes, `\n`, `\r`, U+2028, U+2029, quotes, backticks, `/`, conflict markers, NBSP): #309 took three verify rounds for missing classes (#46, #48, #308, #473, #488).

## Checklist

- [ ] Snapshot diff justified, or none
- [ ] Opt-in option, default = current output
- [ ] Introspection queries qualified by schema and sorted
- [ ] The fixture's output compiles
- [ ] `npm run docs:schema` run, `website/zapatos/` committed
